# 計画: 段階的要約 v3.1（簡易版）

## 背景

設計書・コードが巨大な場合、LLMの入力上限により全文を一括投入できない。
v3.0ではサーバーサイドでジョブ管理を行う複雑な設計だったが、運用負荷が高く、UIも煩雑だった。
本計画では「AIでMarkdown整理」と同様のシンプルな設計に変更し、実用性を高める。

## 目的

- 巨大な設計書・コードを段階的に要約し、最終的に突合レビューに使用できるサマリーを生成する
- サーバーサイドの状態管理を排除し、ブラウザ側で完結する設計にする
- UIを簡略化し、「開始」「停止」のみの操作で自動順次実行する

## 非目的

- サーバーサイドでのジョブ永続化（v3.0の機能）
- 複数ブラウザ/セッション間での再開機能
- 設計書とコードの自動紐付け

## v3.0からの主な変更点

| 観点 | v3.0 | v3.1 |
|------|------|------|
| データ保存 | サーバー側（ファイルシステム） | ブラウザ側（state） |
| 出力形式 | 構造化JSON | サマリー本文（Markdown） |
| UI操作 | セクションごとに手動実行 | 自動順次実行（開始/停止のみ） |
| ジョブ管理 | 複雑（version, failed_sections等） | 不要 |
| チャンク分割 | バックエンド | フロントエンド |
| API | 7エンドポイント | 1エンドポイント |

## 設計

### 処理フロー

```
1. ユーザーが設計書/コードのMarkdownを入力
2. 「段階的要約を開始」ボタン押下
3. フロントエンドでチャンク分割を実行（見出しベースでパース）
4. フロントエンドでチャンクごとに順次要約APIを実行
   - 各チャンクの要約結果をブラウザ側で累積
   - 進捗状況をリアルタイム表示
   - 「停止」ボタンで中断可能（そこまでの結果は保持）
5. 全チャンク完了後、累積サマリーを表示
6. 「サマリーでレビュー実行」ボタンでレビューAPIに渡す
```

### API設計

#### 段階的要約API

- **エンドポイント**: `POST /api/progressive-summary`
- **命名理由**: 「段階的に要約を累積する」という動作を表現

**入力**:
```json
{
  "type": "spec" | "code",
  "chunk": { "id": "string", "title": "string", "text": "string" },
  "chunkOutline": "string",
  "currentSummary": "string",
  "policy": "string",
  "llmConfig": "object | null"
}
```

**出力**:
```json
{
  "success": "boolean",
  "chunkSummary": "string",
  "updatedSummary": "string",
  "error": "string | null"
}
```

**処理**: 1チャンクを要約し、累積サマリーに統合して返す

### プロンプト設計

#### 入力として渡す情報

1. **全体チャンクの構成（chunkOutline）**: どのようなチャンクがあるかの一覧
2. **途中までの要約（currentSummary）**: これまでのチャンクの要約結果
3. **対象チャンク（chunk.text）**: 今回要約するチャンクの本文
4. **要約方針（policy）**: ユーザーが編集可能な注意事項

#### 出力形式

- JSONではなく、**Markdown形式のサマリー本文**を返す
- 累積サマリーに追記・統合しやすい形式

#### プロンプト例（設計書用）

```
あなたは設計書の段階的要約アシスタントです。

## 指示
与えられたチャンクを要約し、現在のサマリーに統合してください。

## ルール
- 要約や推測は禁止。原文の意味を変えない。
- 出力はMarkdown形式で、以下の観点で整理する：
  - 機能一覧
  - 入力仕様
  - 出力仕様
  - 制約・条件
  - 例外処理
  - 非機能要件
- 重複する内容は統合し、矛盾があれば明記する。

## 追加の注意事項
{policy}

## 全体構成
{chunkOutline}

## 現在のサマリー
{currentSummary}

## 対象チャンク: {chunk.title}
{chunk.text}

## 出力
統合後のサマリー全文をMarkdown形式で出力してください。
```

### フロントエンド設計

#### コンポーネント構成

```
ProgressiveSummaryPanel/
├── ProgressiveSummaryPanel.tsx  # メインコンポーネント
├── ChunkProgress.tsx            # 進捗表示
└── SummaryResult.tsx            # 結果表示
```

#### 状態管理（ブラウザ側）

```typescript
interface ProgressiveSummaryState {
  type: 'spec' | 'code'
  chunks: Chunk[]               // 分割されたチャンク一覧
  currentIndex: number          // 処理中のインデックス
  currentSummary: string        // 累積サマリー
  chunkSummaries: Map<string, string>  // 各チャンクの要約
  status: 'idle' | 'summarizing' | 'stopped' | 'completed' | 'error'
  error: string | null
}
```

#### UI要素

1. **方針入力欄**: テキストエリア（デフォルトテンプレート付き）
2. **開始/停止ボタン**: 処理の開始と中断
3. **進捗表示**: `処理中... (3/10) チャンク名`
4. **チャンク一覧**: 完了/処理中/未処理のステータス表示
5. **サマリー表示**: 累積サマリーのプレビュー
6. **採用ボタン**: サマリーをレビュー入力として使用

## エラー処理

| パターン | 検出方法 | ユーザーへの表示 | 対応 |
|----------|----------|------------------|------|
| トークン超過 | API応答コード | 「チャンクが長すぎます」 | 該当チャンクをスキップ、手動分割を促す |
| APIエラー（5xx） | API応答コード | 「サーバーエラー（n回実行）」 | 自動リトライ（最大1回）後、手動再実行を促す |
| タイムアウト | 応答時間 > 180秒 | 「タイムアウト。再試行してください」 | 自動リトライ（最大1回）後、手動再実行を促す |

### 中断時の挙動

- 「停止」ボタンで処理を中断可能
- 中断時点までの累積サマリーは保持される
- 「再開」ボタンで続きから再開可能（ブラウザを閉じなければ）

## 実装ステップ

### Phase 1: バックエンドAPI

1. `POST /api/progressive-summary` の実装
   - プロンプト生成（設計書用/コード用）
   - LLM呼び出し
   - サマリー統合

### Phase 2: フロントエンドUI

2. チャンク分割ロジックの実装
   - `splitMarkdownToChunks` 関数
   - 見出しベースのパース処理
3. `ProgressiveSummaryPanel` コンポーネントの作成
   - 方針入力欄
   - 開始/停止ボタン
   - 進捗表示
4. チャンク順次実行ロジックの実装
   - 状態管理
   - API呼び出しループ
   - 中断/再開処理
5. サマリー結果表示と採用機能
   - プレビュー表示
   - レビュー入力への反映

### Phase 3: 統合とテスト

6. レビュー画面への組み込み
7. エラー処理の実装
8. 動作検証
