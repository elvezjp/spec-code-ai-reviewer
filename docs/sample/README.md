# サンプルファイル（設計書とソースコード）

AIレビュアーによる設計書とコードの突合レビューを体験するためのサンプル一式です。

## ファイル構成

| ファイル | 内容 |
|---|---|
| [注文キャンセル設計書.xlsx](./注文キャンセル設計書.xlsx) | 注文キャンセルAPIのExcel設計書（概要 / 処理フロー / 機能仕様 / エラー一覧 の4シート） |
| [CancelOrderService.java](./CancelOrderService.java) | 対応するJava実装（意図的な不整合を含む） |

## 使い方

1. AIレビュアーの「設計書」欄に `注文キャンセル設計書.xlsx` をアップロードし、Markdownに変換する
2. 「プログラム」欄に `CancelOrderService.java` をアップロードし、行番号を付与する
3. レビューを実行し、指摘と根拠（要件ID・コード行番号）を確認する

## 仕込んであるExcel→Markdown変換の難所

単純なパーサー（markitdown など）でMarkdown化すると情報が欠落・崩壊する箇所を意図的に仕込んであります。

| 箇所 | 内容 |
|---|---|
| 全シートの帳票ヘッダー | セル結合（タイトルの横結合＋承認・作成欄の縦結合）を使ったヘッダー。表としてパースすると `NaN` 混じりの崩れた行が先頭に混入し、本来の表ヘッダーがデータ行に埋没する |
| 処理フロー（2シート目） | 処理手順をセルの表ではなく図形（フローチャート）と図中テキストで記述。テキスト抽出ベースの変換ではフロー内容（REQ-001〜009 の分岐・エラーコード）が一切取得できない |

## 仕込んである不整合（アンサーキー）

| 分類 | 要件 | コード | 内容 |
|---|---|---|---|
| ズレ | REQ-003（期限24時間） | `CANCEL_LIMIT_HOURS = 48` | キャンセル期限が仕様24時間に対し実装48時間 |
| ズレ | REQ-002（SHIPPED / DELIVERED 不可） | `getStatus() == OrderStatus.SHIPPED` | DELIVERED（配達完了）がキャンセル可否判定から漏れている |
| ズレ | REQ-003（期限超過は E-410） | `E-500` を返却 | 期限超過時のエラーコードが仕様と異なる |
| ズレ | REQ-004（商品代金＋送料の全額返金） | `refundAmount -= order.getUsedPoints()` | 返金額からポイント利用分を差し引いており全額返金になっていない |
| 未実装 | REQ-005（キャンセル操作ログの記録） | 該当処理なし | 操作ログを記録していない |
| 未実装 | REQ-006（キャンセル完了メール送信） | 該当処理なし | 顧客への通知が実装されていない |
| 説明不足 | 仕様に記載なし | GOLD会員の期限スキップ分岐 | 仕様は「期限の例外は設けない」だが、実装にゴールド会員の例外がある |
| ズレ | REQ-007（C01〜C04 以外は E-400） | `normalizeReasonCode` が未知コードを C04（その他）に丸める | 不正な理由コードでもエラーにならず処理が続行される。コンパイル・lintは通り、単体では自然に見える実装 |
| ズレ | REQ-008（CANCELLED への再キャンセルは E-409） | `getStatus() == OrderStatus.CANCELLED` で `accepted` を返す | 二重キャンセルをべき等な成功として扱っており、仕様の E-409 と異なる。コンパイル・lintは通り、設計書との突合でのみ検出できる |

※ REQ-009（引当在庫の解放）は `releaseInventory` で仕様どおり実装してあります（正解側のサンプル）。

※ AIレビューの結果は毎回同一とは限りません。上記がすべて検出されるとは限らず、別の指摘が出ることもあります。
