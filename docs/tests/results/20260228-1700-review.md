## NG項目の詳細

### C5: 入力のサニタイズ

**指摘1: `SplitMarkdownRequest.filename` / `SplitCodeRequest.filename` のパストラバーサル未検証**（重要度: 中）

- `versions/v0.9.0/backend/app/routers/split.py:87-88`, `split.py:227-228`
- `request.filename` に `../../etc/passwd` のようなパストラバーサル文字列が含まれていた場合、`os.path.join` が `tmpdir` を無視する可能性がある
- `os.path.basename(request.filename)` の使用、またはファイル名に `..` や `/` が含まれないことの検証を推奨

**指摘2: CORS設定がデフォルトで全オリジン許可**（重要度: 中）

- `versions/v0.9.0/backend/app/main.py:24-25`
- 環境変数 `CORS_ORIGINS` 未設定時にデフォルトが `*`（全オリジン許可）かつ `allow_credentials=True`
- デプロイ時の設定漏れでCSRF等のリスクが生じる

**指摘3: `SummarizeRequest.targetType` のバリデーション不足**（重要度: 低）

- `versions/v0.9.0/backend/app/models/schemas.py:566`
- `targetType` が `str` 型で定義されているが、コメントでは `"design" | "code" | "review_result"` に限定すべきことが示唆されている
- `Literal["design", "code", "review_result"]` への変更を推奨

**指摘4: ファイルアップロードの Content-Type ヘッダ未検証**（重要度: 低）

- `versions/v0.9.0/backend/app/routers/convert.py:30-85`

- 後段パーサーで不正ファイルは失敗するため実質的被害は限定的

## 改善提案

### C5: 入力のサニタイズ

#### 指摘1: パストラバーサル対策

`split.py` の2箇所で `request.filename` をそのまま `os.path.join` に渡している。`os.path.basename()` でディレクトリ成分を除去する。

```python
# split.py:87 (split_markdown)
input_path = os.path.join(tmpdir, os.path.basename(request.filename or "input.md"))

# split.py:227 (split_code)
input_path = os.path.join(tmpdir, os.path.basename(request.filename))
```

#### 指摘2: CORS設定の安全なデフォルト化

`allow_credentials=True` と `allow_origins=["*"]` の組み合わせはブラウザが拒否するケースもあるが、意図しない設定漏れを防ぐため、デフォルトをローカルホストに限定する。

```python
# main.py:24-25
cors_origins_str = os.getenv("CORS_ORIGINS", "http://localhost:3000,http://localhost:5173")
cors_origins = [o.strip() for o in cors_origins_str.split(",")]
```

本番環境では `CORS_ORIGINS` 環境変数でデプロイ先のオリジンを明示的に指定する運用とする。

#### 指摘3: `targetType` の型制約

`str` を `Literal` に変更し、Pydantic のバリデーションで不正値を自動的に拒否する。

```python
# schemas.py:566
from typing import Literal

class SummarizeRequest(BaseModel):
    """要約APIのリクエスト"""
    text: str
    targetType: Literal["design", "code", "review_result"]
    llmConfig: LLMConfig | None = None
```

#### 指摘4: Content-Type ヘッダ検証

拡張子チェックに加え、Content-Type の簡易チェックを追加する。ただし、クライアント側で Content-Type が正しく設定されない場合もあるため、警告レベルに留める。

```python
# convert.py:42行目付近に追加
ALLOWED_CONTENT_TYPES = {
    "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",  # .xlsx
    "application/vnd.ms-excel",  # .xls
    "application/octet-stream",  # 汎用バイナリ（ブラウザのフォールバック）
}

if file.content_type and file.content_type not in ALLOWED_CONTENT_TYPES:
    return ConvertResponse(
        success=False,
        filename=filename,
        error=f"Content-Type '{file.content_type}' は対応していません。Excel ファイルを選択してください。",
    )
```
