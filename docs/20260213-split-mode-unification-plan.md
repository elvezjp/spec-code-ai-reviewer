# 分割レビュー: 一括/分割の統合選択プラン

作成日: 2026-02-13

## 背景/問題
現在は設計書とコードを個別に「一括/分割」選択できるため、片側だけ分割となるケースが発生する。結果として構造マッチングに片側の MAP が空で渡され、グループ生成が不安定になり、レビュー品質が下がる。

## ゴール
- 設計書とコードを「両方まとめて」一括/分割を選べるようにする。
- 片側だけ分割の状態を原則発生させない。
- UI と実行フローを単純化し、ユーザーの意図と実装が一致するようにする。

## 非ゴール
- md2map / code2map の分割ロジック自体の変更
- 構造マッチングのプロンプトや LLM 出力仕様の変更

## 現状整理（要点）
- UI で `documentMode` と `codeMode` を個別選択可能。
- 片側だけ split の場合、構造マッチングに渡す MAP が空になり、グループが不安定。
- 分割レビューのフロー自体は「どちらかが split なら」実行される。

## 方針
「レビュー方式」を 1 つの選択肢に統合する。
- `reviewMode = 'batch' | 'split'`
- `split` 選択時は **設計書とコードの両方**を分割してから構造マッチングへ。
- 片側だけ分割は UI/ロジック両面で禁止。

## 仕様（提案）
1. UI
- 設定UIは「一括レビュー」「分割レビュー」の2択にする。
- 分割レビューを選んだ場合、両方の分割が実行されることを明記。
- 未対応言語などで code2map が分割できない場合は、
  - エラー表示して実行を止める もしくは
  - 一括レビューへ自動フォールバック（要件次第）

2. 分割プレビュー
- 現行: 片側のみ分割可能
- 変更後: `reviewMode === 'split'` の時だけ、設計書・コードの両方を分割。
- 成功条件: 双方の分割結果が揃っていること。

3. 構造マッチング
- `reviewMode === 'batch'` の場合は呼ばない。
- `reviewMode === 'split'` の場合は、両側の MAP/INDEX を必ず渡す。

4. グループレビュー
- `split` の時のみ実行。
- グループ単位でセクション/シンボルの内容を渡す。

## 影響範囲
- `frontend/src/features/reviewer/hooks/useSplitSettings.ts`
- `frontend/src/features/reviewer/components/SplitSettingsSection.tsx`
- `frontend/src/features/reviewer/index.tsx`
- `frontend/src/features/reviewer/types/index.ts`
- 既存 split API (`/api/split/*`) はそのまま利用可能

## 実装ステップ（案）
1. 型定義の統合
- `SplitSettings` から `documentMode` / `codeMode` を削除
- `reviewMode`（batch/split）を追加

2. UI 統合
- 「設計書/コード個別」のラジオ/トグルを削除
- 「一括/分割」の単一トグルに置き換え
- 未対応言語/未分割条件のバリデーション表示を追加

3. 分割プレビューのロジック変更
- `reviewMode === 'split'` のみで両方分割
- 片側しか分割できない場合は明示的に失敗扱い

4. 分割レビュー実行フロー変更
- 構造マッチング・グループレビューは `reviewMode === 'split'` の時のみ実行
- `reviewMode === 'batch'` は従来の `/api/review` へ

5. テスト更新
- 既存 split プレビュー・split review のテストを更新
- 片側分割が行われないことの確認

## 未決事項
- code2map 非対応言語を含む場合の挙動（エラー停止 vs 自動フォールバック）
- 分割レビュー時の最小要件（設計書なし/コードなしの扱い）
